این تحویل بر پایهٔ commit `2a0d8f4867b438d9a62a847295d1a95f3dfbae08` و [پیش‌نویس مرحلهٔ ۴، شمارهٔ ۴۸](https://github.com/mehranyahya/project-genesis/pull/48) است. ادغام آن به مراحل ۱ تا ۴ وابسته است. **آماده‌سازی فنی و بستهٔ تحویل محتوا انجام شده‌اند؛ مرحلهٔ ۵ با عکس و متن نهایی و پذیرش Preview هنوز تکمیل نشده است.**

برای شمارش رسانهٔ تأییدشده، فعال‌بودن صاحب رکورد، تأیید حریم خصوصی، وجود مرجع رضایت و متن جایگزین بررسی شدند. اطلاعات مشتری، متن واقعی تماس، کلید، تصویر خصوصی یا مدرک رضایت استخراج یا عمومی نشدند. دیتابیس و Storage تغییر نکردند. راهنمای Supabase و Changelog جاری برای محدودهٔ بررسی خوانده شدند؛ قابلیت جدید Supabase استفاده نشده است.

## تغییرات آماده‌شده

صفحهٔ اول اکنون از تنظیم انتخاب‌های مستقل فارسی/انگلیسی استفاده می‌کند. عکس ورودی، نسخهٔ موبایل، سه عکس خدمات و سه پروژه باید صریحاً انتخاب شوند. تنظیمات فعلاً خالی‌اند؛ نمونهٔ جعلی، URL خارجی یا اطلاعات خصوصی وارد نشده است.

برای هر عکس، انتخاب با ارجاع عمومی پروژه و Hash عمومی عکس خروجی انجام می‌شود؛ شناسه از Media DTO رسمی گرفته می‌شود. در بازبینی، انتخاب با شمارهٔ گالری کنار گذاشته شد، چون جابه‌جایی یا حذف عکس می‌توانست تصویر دیگری را به نقش حساس ورودی برند منتقل کند. انتخاب نهایی با تغییر ترتیب گالری ثابت می‌ماند؛ فایل حذف‌شده یا تغییرکرده بدون جایگزین ضمنی، ناموجود می‌شود.

Adapter رسمی پرتفولیو فقط هنگام وجود انتخاب معتبر فراخوانی می‌شود و فقط یک بار برای صفحه. صفحهٔ بدون انتخاب همچنان کاتالوگ محصول یا نمونه‌کار را برای پرکردن بخش‌ها واکشی نمی‌کند. فیلتر زبان پیش از انتخاب عکس، پروژه و راهنما انجام می‌شود. محتوای بدون Locale فارسی محسوب می‌شود و وارد انگلیسی نمی‌شود.

قواعد برابری سه خدمت حفظ شده‌اند: مجموعهٔ ناقص تصاویر خدمات به سه کارت متنی می‌انجامد؛ کمتر از سه پروژهٔ معتبر و متفاوت، بخش آثار منتخب را فعال نمی‌کند. عکس‌های خدمات و آثار منتخب با `contain` روی Stage خنثی نمایش داده می‌شوند تا تصویر عمودی یا افقی برای قاب بریده نشود. ورودی high priority است و شش قاب پایین صفحه lazy هستند؛ CSS درون‌خطی اضافه نشده است.

دستور `bun run design:readiness` فقط Artifactهای محلی پاک‌سازی‌شده و صفحات Git را می‌خواند. خروجی، نام ثابت بررسی‌ها و تعدادهاست؛ عنوان محصول، متن صفحه، تماس، مسیر عکس و شناسهٔ پروژه را چاپ نمی‌کند و به Supabase یا شبکه وصل نمی‌شود. آنچه می‌سنجد وجود ورودی‌های طراحی است، نه صحت حقوقی، قیمت، تحقق پروژه یا ظاهر واقعی.

در نسخهٔ فعلی، این دستور ۲۳ کمبود ضروری و ۳ مورد اختیاری تعویق‌شده گزارش می‌کند و با Exit Code ۱ تمام می‌شود؛ این نتیجهٔ درستِ مخزن بدون محتواست، نه شکست تست کد. [Snapshot آمادگی](design-phase-5-readiness-20261008.json) ثبت شده است. حتی موفقیت همهٔ بررسی‌های محتوا به‌تنهایی `readyForPublication` را true نمی‌کند؛ پذیرش Preview باید جدا انجام شود. این دستور به Gate انتشار یا CI موجود اضافه نشده و آن‌ها ضعیف نشده‌اند.

## بستهٔ آماده‌سازی برای مالک

[فهرست دقیق محتوای لازم](content-handoff-fa.md) شامل سوژهٔ عکس‌ها، نسبت و اندازه، توضیح فارسی/انگلیسی، مشخصات صفحات خدمات، اطلاعات برند و شرایط، نحوهٔ اتصال و آزمون Preview است:

- صفحهٔ اول: ۸ فایل منبع، شامل دو خروجی ورودی، سه عکس خدمت و سه عکس پروژه؛ هفت قاب تصویر روی صفحه.
- شروع پیشنهادی کاتالوگ: سه مدل واقعی، هرکدام سه عکس؛ ۹ فایل دیگر. سه مدل پیشنهاد محتواست و الزام فنی نیست.
- ویدیو برای نسخهٔ نخست لازم نیست؛ هیچ رسانهٔ خودکار، انیمیشن جدید یا بستهٔ جدید اضافه نشده است.

بودجهٔ واقعی خروجی عکس در عرض‌های ۳۲۰/۶۴۰/۱۲۸۰، برای هر فایل WebP یا AVIF، ۳۰/۷۰/۲۲۰KiB است. عدد ۸۰ در گزارش قبلی مرحلهٔ ۴ اشتباه نگارشی بود و اصلاح شد؛ کد از ابتدا ۷۰ داشت و تغییر نکرد.

## حجم خروجی و بررسی‌ها

Fixtureها صرفاً در تست‌اند؛ داخل محتوای عملیاتی یا UI پیش‌فرض وارد نشده‌اند.

تست ساختاری صفحهٔ اول با Loader جدید هماهنگ شد و آزمون رفتاری به‌طور واقعی بررسی می‌کند که صفحهٔ بدون انتخاب Adapter پرتفولیو را صدا نمی‌زند. هیچ تست قیمت، ثبت درخواست، حریم خصوصی یا امنیت حذف، Skip یا ضعیف نشد. نتیجه و لینک GitHub Actions در توضیحات PR همین مرحله ثبت می‌شوند.

## کار باقی‌مانده برای تکمیل مرحلهٔ ۵

مالک باید بستهٔ عکس‌ها، اطلاعات واقعی برند/خدمات و متن‌های تأییدشده را آماده کند. قبل از انتشار دوزبانه، ورود ترجمهٔ محتوای واقعی و قرارداد Terms ترجمه‌شده نیز باید پیاده‌سازی و بررسی شوند؛ راهنما اختیاری و هنوز متصل‌نشده است.

بازبینی عکس، RTL/LTR، موبایل، ۳۲۰px، زوم ۲۰۰٪، فوکوس/کیبورد، قارئ صفحه، Reduced Motion، گالری با خطای شبکه و Retry، ثبت درخواست تا کد پیگیری و اندازه‌گیری واقعی باید در Preview انجام شوند. آزمون‌های SSR و Strict dry-run جای اجرای مرورگر و Worker واقعی نیستند. بررسی بصری مرورگر در این محیط در دسترس نبود؛ اجرای Preview محلی در مرحلهٔ قبل با `uv_interface_addresses returned Unknown system error 1` متوقف شده بود و از مسیر جایگزین برای دورزدن آن استفاده نشد.

روش و معیار سنجش در بستهٔ محتوا آمده‌اند؛ هدف CWV کاربران در صدک ۷۵ است، و میانهٔ پنج اجرای آزمایشگاهی فقط مقایسهٔ کنترل‌شده فراهم می‌کند. منابع فنی معیارها [web.dev](https://web.dev/articles/vitals)، [Google Search](https://developers.google.com/search/docs/appearance/core-web-vitals) و [Optimize LCP](https://web.dev/articles/optimize-lcp) هستند. دربارهٔ سرعت نهایی، رتبهٔ سئو یا آمادگی انتشار این نسخه، نتیجهٔ اثبات‌نشده اعلام نمی‌شود.
