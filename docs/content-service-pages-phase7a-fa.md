# مرحلهٔ ۷A — اتصال متن خدمات و هویت مشترک

تاریخ: ۲۰۲۶-۱۰-۱۳، تهران. مبنا: `4bb044b27a6a66d606fdb60e8e7e6ea93e59c6da`، [Draft ۵۹](https://github.com/mehranyahya/project-genesis/pull/59). شاخهٔ مستقل: `design/services-phase7-20261013`.

متن ساختمانی پیش از این در منبع صفحه قابل تعریف بود، اما به View نمی‌رسید؛ ساخت سفارشی منبع توضیح اختصاصی برند نداشت و پنج دسته را بدون انتخاب صریح مالک نمایش می‌داد. اکنون دو خدمت متن همان زبان را از Adapter رسمی صفحه می‌خوانند و تنها دسته‌های صریحاً تأییدشدهٔ ساخت سفارشی نمایش داده می‌شوند. توضیح سئوی پرتفولیو هم هر سه خدمت را پوشش می‌دهد.

**این بسته بخش ۷A است؛ مرحلهٔ ۷ کامل نیست.** بستهٔ ۷B مسیر رسانهٔ خدمات، مصرف رسانهٔ ساختمانی و بازبینی انتخاب عکس/Referral را ادامه می‌دهد. هفت مرحلهٔ اصلی، ۷ تا ۱۳، همچنان باقی‌اند؛ این شمار تعداد نوبت‌های کار نیست. پذیرش واقعی S3، متن/عکس مالک، Preview/E2E و انتشار جدا و بازند.

## تغییر رفتار

| مورد               | رفتار قابل بررسی در کد و آزمون                                                                                                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ساختمانی           | `getPage("building-stone", locale)` هم‌زمان با Site/Terms خوانده می‌شود؛ عنوان/متن محدود و امن به View، عنوان/شرح SEO به Head می‌رسند. فرم و قرارداد قیمت/درخواست حفظ شده‌اند.                    |
| ساخت سفارشی        | Slug محتوایی `stoneworks` به Allowlist اضافه شد؛ Route عمومی تازه یا Adapter نهم ساخته نشد. متن از `getPage("stoneworks", locale)` به View مشترک lazy می‌رسد.                                     |
| دسته‌های ارائه‌شده | صفحهٔ منتشرشدهٔ ساخت سفارشی به `stoneworkCategories` صریح نیاز دارد. فقط پنج شناسهٔ عملیاتی موجود، بدون تکرار و با ترتیب تأییدشده مجازند. دو ترجمهٔ منتشرشده شناسه/ترتیب یکسان دارند.             |
| منبع غایب          | متن یا قاب خالی معرفی ساخته نمی‌شود؛ نسخهٔ انگلیسی از فارسی پر نمی‌شود. صفحهٔ خدمت بدون متن معتبر `noindex` است. ساخت سفارشی بدون تأیید، پنج Offering نمی‌سازد؛ لینک درخواست عمومی موجود می‌ماند. |
| فهرست خالی مصوب    | متن واقعی می‌تواند بدون کارت دسته نمایش داده شود و اقدام عمومی داشته باشد. این حالت از فقدان تأیید جداست؛ هیچ دستهٔ تازه‌ای به‌طور ضمنی انتخاب نمی‌شود.                                           |
| متن انگلیسی        | عنوان، متن و SEO صفحهٔ منتشرشدهٔ انگلیسی با نویسه‌های فارسی/عربی رد می‌شوند؛ Draft می‌تواند ناتمام باشد. این کنترل، کیفیت یا درستی معنایی ترجمه را اثبات نمی‌کند.                                 |
| Metadata مشترک     | توضیح پرتفولیو: «نمونه‌کارهای سنگ مزار، سنگ ساختمانی و ساخت سفارشی»؛ ترجمهٔ انگلیسی موجود آن استفاده می‌شود. توضیح ساخت سفارشیِ غایب، فهرست خدمات تأییدنشده را وعده نمی‌دهد.                      |
| هویت و اقدام عمومی | ناوبری، خانه و مدل انتخاب پروژه‌ها سه خدمت را حفظ می‌کنند؛ هدر/پاورقی/تماس/فرم هویت و تماس را از Site می‌خوانند. بدون هاردکد برند/تماس موقت.                                                      |

شناسهٔ دسته‌ها هنوز `sculpture_art`, `water_landscape`, `architectural_elements`, `furniture_interiors`, `monuments_bespoke` است. متن/کاربرد کارت‌های منتخب نیز باید با خدمات واقعی مالک تطبیق داده و تأیید شود. تعریف Enum درخواست به‌تنهایی تأیید ارائهٔ تمام خدمات نیست. کلیک دسته همان شناسه را به `/quote` یا `/en/quote` می‌برد؛ اطلاعات خصوصی و ابعاد وارد URL نمی‌شوند و آزمون‌های قبلی حفظ اطلاعات فرم پابرجایند. انتخاب خالی از مسیر عمومی، دستهٔ فرضی نمی‌سازد.

Page DTO فقط فیلد عمومی فهرست دسته را در همین Slug می‌گیرد؛ وضعیت بازبینی یا متن خام منبع در Route وارد نمی‌شود. Repository فهرست را Clone می‌کند تا تغییر خروجی یک خواندن، Artifact خواندن بعدی را تغییر ندهد. Source و Model نامعتبر به Offering پیش‌فرض تبدیل نمی‌شوند. نمایش متن با Renderer محدود موجود است؛ کتابخانه، گرادیان، انیمیشن، فونت یا افکت تازه اضافه نشد. شکل پنج‌فیلدی Media و قرارداد هشت Adapter تغییر نکردند.

## آزمون‌ها و بررسی‌ها

| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |

| آزمون متمرکز نخست                                       | ۶۳ مورد موفق؛ سپس آزمون جدید Readiness و بازبینی قرارداد ساختمانی در مجموعهٔ نهایی نیز پاس شدند.     |

| Build، آماده‌سازی/تأیید Artifact، Strict Worker dry-run | موفق؛ صرفاً ساخت و بسته‌بندی محلی، بدون Upload/Deploy                                                |
| Readiness                                               | ۲۴ required blocked، سه deferred، یک pass؛ `readyForPublication=false`                               |
| Release content                                         | exit 1 مورد انتظار؛ متن قانونی/ساختاری واقعی هنوز غایب‌اند                                           |

Fixture CLI واقعی متن دو خدمت و دسته‌ها را از فایل‌های موقت کامپایل کرد؛ اختلاف شناسه/ترتیب ترجمه، پیش از بازنویسی هر دو Artifact رد شد. Parser و Model نقص تأیید، Slug نامعتبر، فهرست نامعتبر/تکراری، Draft و متن ترجمه‌نشده را بررسی کردند. Readiness دو Check تازه برای توضیح/دستهٔ واقعی ساخت سفارشی در هر زبان دارد؛ افزایش از ۲۲ به ۲۴ blocked، دو نیاز محتوایی تازهٔ قابل سنجش است، نه دو شکست Runtime.

Fixture جدا Repository، هشت Adapter، Factory، Router حافظه، View واقعی و SSR دو خدمت را در دو زبان اجرا کرد: متن همان زبان، یک H1، SEO واقعی، دستهٔ انتخاب‌شده، نبود fallback انگلیسی، noindex منبع غایب و استقلال Clone. رندر کارت‌ها همهٔ پنج شناسه را با دادهٔ مصوب مصنوعی آزمود و زیرمجموعهٔ یک دسته و حالت بدون تأیید را جدا بررسی کرد. HTML خام/لینک `javascript:` قابل اجرا نشد. آزمون‌های فرم، قیمت، امنیت، Terms، Referral و حفظ متن خصوصی حذف یا Skip نشدند.

اولین اجرای کامل یک Assertion قدیمی داشت که `getPage` را در ساختمانی ممنوع می‌دانست؛ قرارداد آن با الزام مثبت `getPage` همان زبان و Terms به‌روز شد و اتصال واقعی مستقل آزموده شد. Typecheck نیز کلید ترجمهٔ تکراری و مقدار `undefined` در Head را آشکار کرد؛ کلید موجود دوباره استفاده و مقدار غایب صریحاً `null` شد. پس از اصلاح، مجموعهٔ کامل و Gateهای مرتبط دوباره موفق بودند. CI همان Head در وضعیت GitHub و گزارش جامع ثبت می‌شود؛ موفقیت CI قبلی به نسخهٔ تازه نسبت داده نمی‌شود.

## حجم خروجی عمومی

[نام، اندازه و SHA-256 تمام فایل‌ها](content-service-pages-bundle-20261013.json)، از دو Build تازه با Dependency قفل‌شده و محتوای خالی یکسان:

| مجموع فایل‌ها         |           مبنا |     پیشنهادی |       تغییر |
| --------------------- | -------------: | -----------: | ----------: |
| ۱۹ JS، خام            |        ۵۳۱٬۸۹۵ |      ۵۳۳٬۳۵۷ | +۱٬۴۶۲ بایت |
| همان JSها، مجموع gzip |        ۱۶۶٬۹۹۶ |      ۱۶۷٬۴۶۵ |   +۴۶۹ بایت |
| یک CSS، خام/gzip      | ۲۶٬۲۷۶ / ۶٬۲۴۸ | دقیقاً برابر |         صفر |
| دو WOFF2، خام         |        ۱۳۰٬۹۷۲ | دقیقاً برابر |         صفر |

CSS و فونت از نظر نام/اندازه/SHA برابرند؛ افزایش کل JS فشرده کمتر از نیم KiB است. gzip با Python level 9 و mtime صفر اندازه‌گیری شد؛ مجموع تمام فایل‌هاست، نه دانلود اولیه، Transfer واقعی CDN یا درصد افت سرعت. Renderer موجود مجدداً استفاده می‌شود و View خدمات همچنان lazy است. Lighthouse، CWV، Cache/شبکه و محتوای واقعی در این نوبت سنجیده نشدند. اتصال Loader به Artifact عمومی، Query زندهٔ Supabase یا خواندن Markdown خام در Runtime اضافه نمی‌کند.

## بستهٔ بعد و مرز پذیرش

۷B: مسیر عکس/نمونه‌کار هر خدمت از خروجی پاک‌سازی‌شده، مصرف رسانهٔ ساختمانی، انتخاب عکس با شناسهٔ ثابت و Referral/حالت ناقص در هر دو زبان. سپس مرحلهٔ ۸ راهنما، ۹ Preview، ۱۰ محتوای واقعی، ۱۱ پذیرش رابط/فرم، ۱۲ عملکرد/SEO و ۱۳ تحویل/انتشار طبق قرارداد.

این نوبت Query زندهٔ Supabase، Migration، تغییر Secret/Policy/Workflow انتشار، تصویر یا متن واقعی، درخواست واقعی، پیام، Merge یا Deploy انجام نشد. Media واقعی وارد نشده و پذیرش ظاهری، سرعت و مقصد Preview ادعا نمی‌شود. مجوز یا Gate قبلی مرورگر/Preview با ابزار/میزبان جایگزین دور زده نشد. Rate Limit DB خاموش و شرط بکاپ/Checksum/Restore پابرجاست.

شواهد این بسته فایل و آزمون نسخهٔ مبنا/پیشنهادی‌اند؛ پژوهش تازهٔ رقبا یا تأیید «لوکس‌ترین سایت جهان» نیست. انتخاب دستهٔ صریح، تصمیم مهندسی برای جلوگیری از ادعای خدمت تأییدنشده است؛ تأیید معنایی محتوا، حقوقی و مخاطب واقعی همچنان لازم است. [قرارداد صفحه](../content/pages/README.md)، [بستهٔ محتوا](content-handoff-fa.md) و [برنامهٔ کامل](design-completion-roadmap-fa.md) به‌روز شده‌اند.
