# آماده‌سازی مستقل ۶A — کاتالوگ کامل و انتخاب زبان

تاریخ: ۲۰۲۶-۱۰-۱۲، به وقت تهران. مبنا: `776320e15ccfd4db66d87c01538729f00457e65c`، بستهٔ آفلاین S3. شاخهٔ پیشنهادی: `content/catalog-retrieval-phase6a-20261012`.

این بسته دو نقص مسیر محتوا را اصلاح می‌کند: Build قبلاً تنها یک پاسخ از هر جدول می‌خواند و ممکن بود رکوردهای پس از سقف API را نبیند؛ جست‌وجوی محصول نیز پیش از تشخیص زبان اولین Slug را انتخاب می‌کرد. اکنون خواندن کامل کنترل می‌شود و زبان بخشی از ورودی معتبر جست‌وجو است.

**این آماده‌سازی مستقل کد است. پذیرش S3 زنده، پایان کامل مرحلهٔ ۶ و مجوز Merge/Deploy نیست.** پالت، چیدمان، عکس و متن واقعی تغییر نکرده‌اند. اصلاح DB یا Migration برای این بسته لازم نبود؛ دربارهٔ نیاز مراحل ترجمهٔ بعدی از این نتیجه استنباط نمی‌شود.

## خواندن کاتالوگ در Build

- هر صفحه حداکثر ۱۰۰ ردیف درخواست می‌کند؛ `Range-Unit: items`، `Range` و `Prefer: count=exact` صریح‌اند. تمام Queryهای جدول، حتی Site تک‌ردیفی، ترتیب قطعی با کلید یکتا دارند.
- API ممکن است کمتر از ۱۰۰ ردیف برگرداند. Offset بعدی از تعداد واقعاً دریافت‌شده ساخته می‌شود؛ تعداد کوتاه به‌تنهایی به معنی پایان نیست.
- `Content-Range` با شمارش دقیق، پیوستگی بازه، طول Array، کلید ردیف و ثبات Count کنترل می‌شود. Count غایب/تخمینی، Gap، هم‌پوشانی، تکرار، Shape نامعتبر یا سقف اضافه باعث خطا می‌شوند؛ فهرست ناقص منتشر نمی‌شود.
- همهٔ محصولات فعال، Variant، Option، رسانهٔ محصول، نمونه‌کار و رسانه‌اش، آیتم/رسانهٔ ساختمانی و Site از همین Reader می‌گذرند. سقف قبلی چهار MiB برای **هر پاسخ** حفظ شده؛ مجموع پاسخ‌های جدول یک Build بودجهٔ مشترک ۶۴ MiB و ۲۰۰۰ درخواست دارد. هر مجموعهٔ جدول حداکثر ۱۰٬۰۰۰ ردیف است؛ سقف فرزندان میان Batchها جمع می‌شود. این محدودیت‌ها خطا می‌دهند، رکورد را قطع نمی‌کنند.
- فیلتر شناسه‌های والد در گروه‌های حداکثر ۲۵تایی ساخته می‌شود؛ شناسهٔ نامعتبر، رابطه با والد خارج از همان گروه و تکرار فرزند بین گروه‌ها متوقف می‌شوند. کلید رسانه از ترکیب مالک و Key ساخته می‌شود؛ Key خصوصی در خطا چاپ نمی‌شود.
- رزرو بودجه پیش از خواندن Stream انجام می‌شود تا دو خواندن موازی بودجه را اضافه برداشت نکنند. نزدیک سقف کل، این روش محافظه‌کار ممکن است Build را زودتر متوقف کند؛ رفع آن با حذف کنترل یا انتشار ناقص مجاز نیست.
- نسخهٔ عملیاتی کاتالوگ پیش از خواندن و پس از پردازش کنترل می‌شود؛ اختلاف باعث شکست تولید و حفظ Artifact قبلی می‌شود. نسخهٔ معتبر همان Hash مشترک Server است.

**محدودیت:** Count دقیق و ترتیب ثابت برای نتیجهٔ بدون تغییر، کامل‌بودن پیمایش را بررسی می‌کنند؛ Snapshot تراکنشی چند درخواست HTTP نیستند. Hash عملیاتی فعلی نیز تمام متن/رسانهٔ محصول، Site، ساختمان و پرتفولیو را پوشش نمی‌دهد؛ ABA یا تغییر هم‌تعداد همهٔ محتوا را تضمینی تشخیص نمی‌دهد. هماهنگی/توقف ویرایش هنگام ساخت نهایی و آزمون واقعی منبع همچنان لازم‌اند. شمارش دقیق نیز هزینهٔ Build/DB دارد و روی Request مرورگر اجرا نمی‌شود.

## زبان در Repository و Adapter

- همان هشت نام Adapter حفظ شدند. `getProduct(slug, locale)`، `getProducts({ locale, ... })` و `getPortfolioItems({ locale, ... })` اکنون زبان را در ورودی معتبر تابع Server دارند. پیش‌فرض سازگاری با منبع قدیمی فارسی است.
- تشخیص زبان در Repository **پیش از Limit و انتخاب Slug** انجام می‌شود. دو ترجمه با Slug مشترک همدیگر را پنهان نمی‌کنند؛ ترتیب فارسی/انگلیسی در Artifact اثری بر نتیجه ندارد.
- نبود ترجمه یا رکورد غیرفعال به زبان دیگر برنمی‌گردد. Label نامعتبر در انتخاب کاتالوگ حذف می‌شود؛ دو ترجمهٔ فعال مبهم در همان Slug/زبان خطا می‌دهند.
- Loaderهای فهرست، محصول، مزار سفارشی، پرتفولیو و Referral فرم زبان را صریح می‌فرستند. خانه تنها در صورت تنظیم انتخاب واقعی رسانه، Reader را با همان زبان صدا می‌زند؛ خانهٔ خالی هیچ کاتالوگ نمونه‌کاری دریافت نمی‌کند.
- انتخاب ترجمه شناسه، Amount، نوع قیمت، زمان قیمت، موجودبودن و آرایهٔ Variant/Option را بازنویسی نمی‌کند. قانون نهایی قیمت و ثبت درخواست همچنان Server است.
- Generator فعلی منبع موجود را صریح `fa` علامت می‌زند. **ورود ترجمهٔ انگلیسی واقعی هنوز پیاده‌سازی نشده**؛ این کار محتوای فارسی را ترجمه یا از طریق Label به انگلیسی تبدیل نمی‌کند.
- ابزار Readiness هر دو زبان Repository را جدا می‌خواند، اما قابلیت English source و Guides هنوز `false` است. ۲۳ Check ضروری blocked، سه مورد deferred، و `readyForPublication=false` باقی‌اند.

## شواهد محلی

| بررسی | نتیجه |
| --- | --- |
| نصب Frozen | ۴۴۵ Package؛ Package و Lockfile تغییر نکردند |
| آزمون پروژه | ۸۵۰ pass، صفر fail، ۷۴ فایل؛ ۲۷ آزمون جدید |
| Lint | صفر خطا؛ همان ۲۹ هشدار موجود |
| TypeScript، Edge check، Content check | موفق |
| Dependency audit | صفر Advisory شناخته‌شده؛ Ignore اضافه نشد |
| Build، آماده‌سازی و بررسی Artifact، Strict Worker dry-run | موفق؛ Upload/Deploy نیست |
| Readiness | exit 1 مورد انتظار؛ محتوا و پذیرش واقعی غایب‌اند |

آزمون Reader، ۱۲۰۱ ردیف با مجموع JSON بیشتر از چهار MiB و سقف مصنوعی ۷۳ ردیف سرور را کامل جمع کرد. آزمون CLI واقعی در پوشهٔ موقت، هر نه جدول را پیمایش کرد: یک محصول، ۱۰۰۵ Variant، ۱۰۰۵ Option، یک رسانهٔ محصول، یک نمونه‌کار و رسانه‌اش، ۱۰۰۵ آیتم ساختمانی و ۱۰۰۵ ردیف رسانهٔ تأییدنشده، و یک Site. رسانهٔ تأییدنشده پردازش/منتشر نشد. یک PNG مصنوعی برای دو مالک محصول/پرتفولیو با Sharp به خروجی عمومی تست تبدیل شد؛ هیچ Fixture یا عکس ساختگی وارد Artifact متعهدشدهٔ سایت نشد.

آزمون اتصال Loaderها در فرایند جدا، Factoryهای واقعی را با Adapter مصنوعی اجرا کرد: هر دو زبان، Slug مشترک، مزار سفارشی، پرتفولیو و Referral، و سپس حذف ترجمهٔ انگلیسی. ورود Terms همچنان خالی و ثبت واقعی درخواست ممنوع بود. این آزمون مرورگر یا E2E زنده نیست.

چهار آزمون ساختاری قدیمی به ورودی صریح زبان تغییر یافتند و منع فراخوانی بدون زبان هم به آن‌ها اضافه شد؛ آزمون حذف یا ضعیف نشد. آزمون خانهٔ بدون دریافت کاتالوگ حفظ و آزمون Reader خانه با بررسی پارامتر زبان تقویت شد.

CI همین Head باید Gateهای پروژه و گام اجباری نه سناریوی رمزنگاری بومیِ بستهٔ قبلی را اجرا کند. نتیجهٔ محلیِ بالا جای نتیجهٔ CI، پذیرش منبع Supabase یا محیط واقعی را نمی‌گیرد؛ پیوند و وضعیت CI در تحویل جامع ثبت می‌شوند.

## باقی‌مانده و ادامه

- منبع ترجمهٔ واقعی عنوان/توضیح/SEO/alt، Option و شامل/غیرشامل محصول، پرتفولیو و Site؛ بررسی کمترین تغییر ضروری و حفظ هویت عملیاتی.
- `getPage(slug, locale)`، منبع صریح صفحات Git، Terms/Privacy واقعی هر زبان، همگامی Registry/فرم/صفحه و جلوگیری از پذیرش متن غایب/قدیمی.
- خطای Fatal انگلیسی، Readiness کامل، Sitemap آمادهٔ انتشار و سایر کارهای مراحل ۶ تا ۱۳.
- S3 واقعی: Preview/Access مستقل، Receiver اصلی، کپی ماندگار و Decrypt/Restore مستقل، سپس DB/Storage/ACL/Postgres طبق Gate و مجوز. دریافت کلید خصوصی در گفتگو لازم/مجاز نیست.

این نوبت Query زندهٔ Supabase، Export/Upload عکس واقعی، SQL نوشتنی، Migration، تغییر Secret/Policy، ثبت درخواست، پیام، Merge یا Deploy ندارد. شرط بکاپ/Restore پیش از Migration و خاموش‌بودن Rate Limit حفظ شدند. ابزار یا میزبان جایگزین برای دورزدن محدودیت قبلی Preview/مرورگر استفاده نشد.
