# اصلاح‌های ممیزی پیش از محتوا و محیط زنده

مبنای این بسته PR77 و Commit `ac99e1078d6f9daa319fb8a2a951b2c568a0e476` است. دو یافتهٔ M-01 و M-02 در کد این شاخه اصلاح شده‌اند. این بسته انتشار، Migration یا پذیرش محیط زنده نیست.

## مشکل و رفتار پس از اصلاح

### M-01 — وصلهٔ امنیتی TanStack

نسخه‌های قبلی React Start و Server Core تحت [GHSA-qx66-fv34-fjm8](https://github.com/advisories/GHSA-qx66-fv34-fjm8) بودند. سه وابستگی مستقیم با نسخهٔ دقیق و هماهنگ ثبت شدند:

| بسته | نسخهٔ قبلی نصب‌شده | نسخهٔ جدید |
| --- | --- | --- |
| @tanstack/react-start | 1.168.32 | 1.168.60 |
| @tanstack/react-router | 1.170.18 | 1.170.41 |
| @tanstack/router-plugin | 1.168.23 | 1.168.42 |
| @tanstack/start-server-core، غیرمستقیم | 1.169.17 | 1.169.39 |

Lockfile تازه و نصب Frozen موفق است. Audit از دو ردیف بحرانی برای یک GHSA به **صفر هشدار** رسید. این نتیجهٔ graph نصب‌شده در زمان اجراست؛ تضمین نبود آسیب‌پذیری آینده نیست.

ارتقا قراردادهای Router را نیز تغییر داد. ورودی Error Boundary اکنون `unknown` است و پردازش امن خطا حفظ شده. علامت جدید `_notFound` به کنترل Head اضافه شد؛ آزمون واقعی SSR تأیید می‌کند پاسخ ۴۰۴ همچنان noindex دارد و canonical/alternate/دادهٔ مقالهٔ قبلی را نگه نمی‌دارد.

آزمون‌های موجود با نسخهٔ نصب‌شده هماهنگ شدند: Dehydration فقط شاخهٔ واقعاً رندرشده را منتقل می‌کند، preload یک ماژول خراب دوباره تلاش می‌شود، نتیجهٔ HTTP از قرارداد SSR جدید خوانده می‌شود و Fixture لینک شرایط تمام Exportهای لازم و Store جدید را دارد. کنترل‌های امنیت، Nonce، دادهٔ خصوصی و پاسخ‌های ۲۰۰/۴۰۴/۵۰۰ حذف نشده‌اند. VM فقط انتقال State روتر را اجرا می‌کند؛ دستورهای تغییر DOM متعلق به React در این VM اجرا نمی‌شوند و Nonce تمام Scriptها همچنان کنترل می‌شود.

### M-02 — فرم قدیمی پس از تغییر کاتالوگ

Wrapper ساخت مرحله‌ای اکنون با زبان و نسخهٔ کاتالوگ Key می‌گیرد. تغییر این هویت، انتخاب و فرم قبلی را بازسازی می‌کند. علاوه بر آن، Draft قبل از نمایش با مدل فعلی دوباره ساخته و مقایسه می‌شود. بنابراین حذف محصول/گزینه یا تغییر قیمت با همان نسخه نیز نمی‌تواند فرم آمادهٔ قدیمی را فعال نگه دارد.

این کنترل هنگام Render است؛ منتظر Effect نمی‌ماند. اگر دادهٔ جدید از نظر معنا یکسان باشد، انتخاب و فرم حفظ می‌شوند. تغییر هویت یا نامعتبرشدن انتخاب می‌تواند اطلاعات تماس ارسال‌نشده را نیز با کناررفتن فرم پاک کند؛ ذخیرهٔ پایدار اطلاعات شخصی اضافه نشده است. تلاش درحال ارسال که قبلاً به سرور رسیده باشد با این اصلاح «لغو تراکنش» نمی‌شود؛ اعتبارسنجی سرور همچنان مرجع نهایی است.

آزمون جدید روی کد قبل از اصلاح با «obsolete RequestForm after version in fa» شکست خورد و پس از اصلاح موفق شد. هفت انتقال در هر دو زبان اجرا می‌شوند: نسخهٔ جدید، نسخهٔ غایب، نسخهٔ نامعتبر، کاتالوگ خالی، حذف محصول با نسخهٔ ثابت، تغییر قیمت با نسخهٔ ثابت و تغییر زبان. در هر سناریو کنترل حفظ انتخاب برای شیء تازهٔ هم‌معنا نیز وجود دارد. برای حالت‌های قابل تحویل، خلاصهٔ تازه و Payload واقعی دوباره ساخته و قیمت/نسخه/عنوان کنترل می‌شوند. جمعاً **۱۴ انتقال، fetch=0 و storage=0** است.

Wrapper/Page، Callback و منطق Draft/Payload واقعی‌اند؛ Hook Slot و دادهٔ Loader کنترل‌شده‌اند. این آزمون DOM، React Reconciler، Focus یا سفارش زنده نیست.

## قابلیت تکرار آزمون رسانه

پردازش بومی AVIF در آزمون پیمایش کاتالوگ این محیط حدود ۶ ثانیه طول کشید، ولی والد با پیش‌فرض ۵ ثانیه متوقف می‌شد و به خطاهای زنجیره‌ای Runner می‌رسید. مهلت همان والد ۷۵ ثانیه شد تا فرایند فرزند با سقف قبلی ۶۰ ثانیه فرصت پایان و پاک‌سازی داشته باشد. کنترل تعداد رکوردها، Pagination، Hash و حفظ Artifact قبلی باقی است. آزمون برای زمان بارگذاری سایت طراحی نشده است.
