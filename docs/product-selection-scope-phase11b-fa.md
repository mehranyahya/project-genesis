# اصلاح مستقل ۱۱B: مرز انتخاب و فرم هر محصول

تاریخ: ۲۰۲۶-۱۰-۱۵، تهران. پایه `2e60fc074eda7bf8ca929975615056464c8b605d` از PR75؛ شاخه `ux/product-selection-scope-phase11b-20261015`.

## ایراد بازتولیدشده

صفحهٔ محصول، Variant، گزینه‌ها و Draft را در State نگه می‌دارد. Wrapper مشترک مسیر، هنگام دریافت محصول یا کاتالوگ تازه مرز مشخصی برای آن State نداشت. در اجرای Source، انتخاب Variant دوم و یک گزینه و سپس تغییر دادهٔ مسیر، عنوان/انتخاب جاری را از مدل تازه می‌آورد ولی خلاصه و Source فرم می‌توانستند متعلق به مدل قبلی بمانند. نبود نسخهٔ معتبر نیز فقط دکمهٔ بازبینی تازه را غیرفعال می‌کرد و فرم قدیمی را حذف نمی‌کرد.

این رفتار با کامپوننت و Handlerهای واقعی، Builder واقعی مدل/Draft/Payload و Hook/Loader مصنوعی بازتولید شد؛ Browser/DOM، React Reconciler یا ناوبری واقعی اجرا نشدند. ده انتقال: دو زبان × محصول دیگر، نسخهٔ تازه، نسخهٔ غایب، نسخهٔ نامعتبر و زبان دیگر. قبل، هر ده Draft قبلی را نگه می‌داشتند؛ پس از اصلاح هیچ‌کدام آن را به خلاصه/فرم نمی‌رسانند. Fixture آزمون پس از اصلاح دو خطای ابزار آزمون نیز روی پایه در همان Assertion اصلی شکست خورد؛ نتیجهٔ خطای Fixture به‌عنوان شاهد ایراد برنامه ثبت نشد.

## اصلاح و دلیل

در `src/lib/route-defs/views/product.tsx`، کلید زیرصفحه از زبان، شناسهٔ محصول و نسخهٔ کاتالوگ ساخته شد. تغییر واقعی این هویت، انتخاب/خلاصه/فرم زیر آن را از نو آغاز می‌کند. بازخوانی همان هویت با Object تازه، انتخاب و Draft را حفظ می‌کند. Route، Payload، الگوریتم قیمت، شرط موفقیت و Schema تغییر نکردند؛ پالت/رسانه/فونت/Package تازه نداریم.

[React: Preserving and Resetting State](https://react.dev/learn/preserving-and-resetting-state) نقش Type/Key در حفظ یا بازسازی State را توضیح می‌دهد. [TanStack RouteOptions](https://tanstack.com/router/latest/docs/api/router/RouteOptionsType) تصریح می‌کند مسیر فعال به‌صورت پیش‌فرض با هر ناوبری از نو ساخته نمی‌شود. Source نصب‌شدهٔ `Match.tsx` نیز کلید وابسته به `remountDeps/defaultRemountDeps` را نشان داد؛ در Wrapper و Router پروژه چنین مرزی تنظیم نشده بود. اصل چارچوب از این منابع است؛ انتخاب سه جزءِ کلید، تصمیم اجرایی همین پروژه برای Draft وابسته به زبان/محصول/کاتالوگ است.

**اثر قابل توجه:** با تغییر این هویت، اطلاعات در حال ورودِ فرم زیر محصول نیز حمل نمی‌شوند. این رفتار جلوی ادامهٔ فرم با انتخاب قبلی را می‌گیرد؛ حفظ داده در تعویض محصول/نسخه/زبان وعده داده نمی‌شود. تعامل روی همان هویت بازنشانی نمی‌شود. Focus، اعلان و مناسب‌بودن تجربهٔ تعویض زبان باید در مرورگر واقعی بررسی شوند.

## آزمون و شواهد

- یک رگرسیون رفتاری در `src/lib/route-defs/product-selection-runtime.test.ts`، Source مسیر/صفحه، callback انتخاب، مدل/Draft و ساخت Payload را اجرا می‌کند. Type/Key→Hook slots و Loader مصنوعی‌اند؛ تست اجرای Renderer واقعی نیست.
- در هر ده انتقال، ابتدا Variant دوم/گزینه انتخاب و بازبینی می‌شود. بازخوانی هم‌هویت آن را حفظ می‌کند؛ تغییر هویت Draft و Source فرم را حذف، گزینه‌ها را پاک و Variant نخست مدل جدید را انتخاب می‌کند. با نسخهٔ نامعتبر/غایب بازبینی بسته است؛ با نسخهٔ معتبر، بازبینی تازه Payload را به محصول/Variant/نسخه/مبلغ درست متصل می‌کند.
- Probe قبل/بعد با صفر Fetch و صفر دسترسی Storage حین تعامل ثبت شد. Import چارچوب ممکن است Cache اسکرول خودش را بخواند؛ تلهٔ Storage پس از Import نصب شد تا آن کار به ذخیرهٔ Draft نسبت داده نشود. فیلد قیمتِ Assert نیز با نام واقعی قرارداد، `client_displayed_price`، تطبیق داده شد. Assertion اصلی حفظ و روی پایه دوباره Red شد.
- نصب Frozen با Bun 1.3.14، Prettier و Diff check موفق‌اند. آزمون کامل **۱۰۰۱ Pass، صفر Fail، ۱۰۲ فایل**؛ TypeScript و هر دو Edge check موفق‌اند.
- Lint نخست، Fixture باقی‌مانده از تست موجود SEO را دید؛ همان فایل آزمایشیِ تولیدشده و شناخته‌شده پاک شد و Source/Test تغییر نکرد. Lint نهایی صفر Error و ۲۹ Warning موجود دارد. برای رفع آن، تست یا قانون Lint حذف/تضعیف نشد.
- Audit وابستگی‌ها صفر آسیب‌پذیری شناخته‌شده؛ Build/Content check، Prepare/Verify Artifact و Dry-run سختگیرانهٔ Wrangler 4.97.0 موفق‌اند. راهنمای CLI نصب‌شده، `--dry-run/--strict` را تأیید کرد؛ صفحهٔ شاخص وب به فرمان منتقل شده بود و Click آن خوانده نشد.
- نه سناریوی Native recovery با age v1.3.2 و کلید/بایت آزمایشی موفق‌اند؛ بکاپ/Restore واقعی نیستند. Compile Edge همان منبع قبلی است؛ Changelog رسمی Supabase بعد از خطای Content type نسخهٔ Markdown با HTML خوانده شد و Backend/Schema تغییر نکرد.
