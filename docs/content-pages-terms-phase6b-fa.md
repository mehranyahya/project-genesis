# آماده‌سازی مستقل ۶B — صفحات و پذیرش شرایط هر زبان

تاریخ: ۲۰۲۶-۱۰-۱۲، تهران. مبنا: commit `16aebe5838b1968ec6e2ebcf82afa74f1b785864`، [Draft ۵۷](https://github.com/mehranyahya/project-genesis/pull/57). شاخهٔ پیشنهادی: `content/pages-terms-phase6b-20261012`، وابسته به ۶A.

صفحات Git و شرایط فرم پیش از این زبان را انتخاب نمی‌کردند؛ فرم انگلیسی می‌توانست همان سند فارسی را دریافت کند. اکنون صفحه، فرم و Backend فعال به نسخهٔ بازبینی‌شدهٔ همان زبان وصل‌اند. پس از تغییر شرایط نیز فرم قبل از پذیرش دوباره، صفحهٔ واقعی همان زبان را می‌خواند و Version/Hash آن را با پاسخ Edge مقایسه می‌کند.

**این آماده‌سازی کد است؛ متن حقوقی واقعی، پذیرش S3 و پایان کامل مرحلهٔ ۶ نیست.** پالت، عکس، محتوای واقعی، Package/Lockfile و محیط زنده تغییر نکرده‌اند. Migration، تغییر Request/RPC، قیمت، کاتالوگ و Fingerprint انجام نشده است؛ مجوز Merge/Deploy صادر نشده.

## منبع و Artifact

- [قرارداد منبع](../content/pages/README.md): `content/pages/fa/<slug>.md` و `content/pages/en/<slug>.md`؛ Locale و Slug باید با پوشه/نام فایل برابر باشند. منبع تخت رد می‌شود. هفت Slug رسمی و هشت نام Adapter حفظ شده‌اند.
- کلیدهای Frontmatter و نوع‌ها کنترل می‌شوند؛ Unknown/Duplicate، Canonical زبان اشتباه، فایل/زبان ناشناخته، UTF-8 نامعتبر، Symlink/Hardlink و فایل بیش از ۲۵۶KiB خطا می‌دهند. خواندن بایت محدود و `O_NOFOLLOW` است؛ مقدار منبع در خطا چاپ نمی‌شود.
- Draft هیچ DTO/متن/Hash عمومی تولید نمی‌کند. فقط `published` و `reviewed=true` همراه متن غیرخالی وارد Artifact می‌شوند. این Flagها جای تأیید مالک/حقوقی را نمی‌گیرند.
- Runtime فقط `GIT_PAGES` کامپایل‌شده را می‌خواند؛ فایل Markdown، Parser و Node Crypto وارد Runtime صفحه یا مرورگر نمی‌شوند. نبود ترجمه `null` است، بدون fallback زبان دیگر. نسخهٔ پیش‌فرض API قدیمی فارسی است.
- `getPage(slug, locale)` و Factory صفحات ثابت/تماس، ۴ مسیر فرم و ۴۰۴ ریشه زبان را صریح می‌فرستند. Canonical هر زبان مستقل است؛ Render فرم انگلیسی شامل متن فارسی نیست.
- `content:check` Artifact صفحه و Registry را بدون نوشتن کنترل می‌کند. `content:release-check` Terms و Privacy بازبینی‌شدهٔ هر دو زبان و Artifact ساختاری واقعی را لازم می‌داند؛ Baseline خالی عمداً مسدود است.

## پذیرش Terms و هماهنگی نسخه‌ها

- ترجمه‌های منتشرشده یک Version حقوقی مشترک و دو Hash مستقل دارند. فارسی SHA-256 قرارداد قبلی، `version + LF + normalizedBody` را حفظ می‌کند؛ انگلیسی پیشوند `en + LF` دارد. متن برابر نیز پذیرش زبان‌ها را یکی نمی‌کند.
- Edge فعال از `CURRENT_TERMS_RELEASES` کامپایل‌شده از همان صفحات استفاده می‌کند. برای هر زبان فقط Hash فعلی مجاز است؛ Registry خالی/نامعتبر، اختلاف Version یا Hash تکراری ۵۰۳ می‌دهند. Version/Hash قدیمی ۴۰۹ می‌گیرد.
- شناسهٔ زبان از Hash تأییدشده معلوم می‌شود؛ Field جدید Request/RPC/DB اضافه نمی‌شود. Price/Idempotency/Turnstile و Canonical Fingerprint به همان قرارداد قبلی متکی‌اند.
- `TERMS_UPDATED` علاوه بر متادیتای سازگار قدیمی، `terms_by_locale` دارد. Client Shape، Label، Version مشترک و Hash مستقل را بررسی می‌کند. پاسخ قدیمی بدون زبان فقط در جریان فارسی پذیرفته می‌شود.
- هنگام Update، فرم با GET رسمی، مهلت ۱۰ ثانیه و AbortSignal صفحهٔ همان زبان را دوباره می‌خواند. متن غایب، شبکه/Timeout، اختلاف Hash/Version یا دو Deploy ناهمگام پذیرش را مسدود می‌کند. اطلاعات فرم در حافظه حفظ، تیک پذیرش پاک و برای ارسال بعدی شناسهٔ تازه لازم می‌شود؛ POST خودکار تکرار نمی‌شود.
- تغییر زبان/سند، Epoch تلاش را نامعتبر می‌کند؛ پاسخ دیررس تلاش قبلی قبل و بعد از Refresh اعمال نمی‌شود. پیش از اعمال سند جدید در Effect نیز کنترل ارسال مسدود است. پذیرش واقعی این رفتار در مرورگر برای مرحلهٔ ۱۱ باقی است.
- مسیر قدیمی TanStack ثبت درخواست همچنان مسدود و غیرفعال است؛ Backend فعال Worker→Edge تغییر کرد. Alias فارسی Registry برای سازگاری ابزارها حفظ شد؛ این Alias پذیرش Backend فعال را کنترل نمی‌کند.

وب و Edge باید از نسخهٔ یکسانِ تأییدشده منتشر شوند؛ کنترل تطبیق، Deploy ناهمگام را به پذیرش متن قدیمی تبدیل نمی‌کند. HTML/CDN و خطای شبکه در Preview باید بررسی شوند.

## شواهد این نوبت

| بررسی                                          | نتیجهٔ محلی                                                                    |
| ---------------------------------------------- | ------------------------------------------------------------------------------ |
| Frozen install                                 | ۴۴۵ Package؛ Package/Lockfile برابر مبنا                                       |
| آزمون پروژه                                    | ۸۸۶ pass، صفر fail، ۷۸ فایل؛ ۳۶ آزمون جدید                                     |
| Lint                                           | صفر Error؛ همان ۲۹ Warning قبلی                                                |
| TypeScript / Edge check / Content check        | موفق؛ نتیجهٔ CI همین Head جدا در گزارش جامع ثبت می‌شود                         |

| Build / بررسی Artifact / Strict Worker dry-run | موفق؛ Dry-run خروجی می‌سازد و Upload/Deploy نیست                               |
| Readiness                                      | ۲۳ blocked، سه deferred، `readyForPublication=false`؛ exit 1 مورد انتظار       |
| Release content                                | exit 1 مورد انتظار؛ Terms/Privacy واقعی هر دو زبان و Structured واقعی غایب‌اند |

آزمون‌ها Parser و Hash را با قرارداد قبلی مقایسه، Draft و ورودی نامعتبر را رد و CLI واقعی را در پوشهٔ موقت اجرا کردند؛ کنترل نسخهٔ ناهمگام پیش از بازنویسی دو Artifact انجام شد. Fixture مصنوعی فقط در Test/پوشهٔ موقت بود؛ متن یا عکس ساختگی وارد Artifact متعهدشدهٔ سایت نشد.

Repository/Adapter/Factory واقعی با Artifact مصنوعی در فرایند جدا برای صفحات ثابت، تماس، محصول، مزار سفارشی، ساختمان و Quote اجرا شدند؛ سپس ترجمهٔ انگلیسی حذف و نبود fallback اثبات شد. مسیر واقعی `prepareBusinessRequest` با Registry موقت هر دو Hash را در همان Fieldهای RPC حفظ کرد و Hash قدیمی را رد کرد؛ شبکه/DB اجرا نشد. Render واقعی React در هر دو زبان، غیبت/زبان نادرست سند و لینک شرایط همان زبان را بررسی کرد. نسخهٔ قدیمی، Map نامعتبر و Timeout/Abort نیز آزمایش شدند. این‌ها Browser/E2E زنده نیستند.

پنج Assertion ساختاری قدیمی به انتخاب صریح زبان تغییر یافتند؛ آزمون حذف یا Skip نشد و پوشش جدایی زبان تقویت شد. CI موجود گام اجباری ۹ سناریوی واقعی رمزنگاری آفلاین بستهٔ S3 را نیز حفظ می‌کند؛ نتیجهٔ آن باید متعلق به همین Head باشد.

## هزینهٔ فایل‌های عمومی

مبنا و شاخهٔ پیشنهادی با Lockfile و محتوای خالی یکسان تازه Build شدند. [نام، اندازه و SHA-256 فایل‌ها](content-pages-terms-bundle-20261012.json).

| مجموع فایل‌ها         |           مبنا | پیشنهادی |       تغییر |
| --------------------- | -------------: | -------: | ----------: |
| ۱۹ JS، خام            |        ۵۳۰٬۲۱۰ |  ۵۳۱٬۸۶۶ | +۱٬۶۵۶ بایت |
| همان JSها، مجموع gzip |        ۱۶۶٬۴۷۰ |  ۱۶۷٬۰۱۶ |   +۵۴۶ بایت |
| یک CSS، خام/gzip      | ۲۶٬۲۷۶ / ۶٬۲۴۸ |    برابر |         صفر |
| دو WOFF2، خام         |        ۱۳۰٬۹۷۲ |    برابر |         صفر |
| JS+CSS+WOFF2، خام     |        ۶۸۷٬۴۵۸ |  ۶۸۹٬۱۱۴ | +۱٬۶۵۶ بایت |

CSS و فونت‌ها از نظر نام/اندازه/SHA-256 برابرند. gzip با Python، Level 9 و mtime صفر حساب شد. این مجموع تمام فایل‌های عمومی است، نه دانلود ورودی نخست یا Transfer واقعی CDN؛ از آن درصد افت سرعت، Lighthouse/CWV یا امتیاز SEO ساخته نمی‌شود. Parser/Hash در Build اجرا می‌شوند؛ Runtime کتابخانهٔ جدید و افکت بصری اضافه ندارد. وزن متن واقعی بعداً باید با همان Gate سنجیده شود.

## باقی‌مانده و ادامه

۸ مرحلهٔ اصلی هنوز بازند: باقی ۶ و مراحل ۷ تا ۱۳؛ پذیرش S3 پیش‌نیاز جداست و تعداد نوبت‌ها لزوماً ۸ نیست. بستهٔ بعدی مستقل ۶C است: منبع ترجمهٔ ساختاری محصول/پرتفولیو/Site و Fatal انگلیسی، با حفظ هویت عملیاتی. عکس/متن واقعی و تأیید حقوقی در مرحلهٔ ۱۰؛ Preview، E2E، سنجش عملکرد و انتشار طبق Gateهای مربوط ادامه دارند.

این نوبت Query زندهٔ Supabase، Migration، Export/Upload واقعی، تغییر Secret/Policy، ثبت درخواست مشتری، پیام، Merge یا Deploy اجرا نشد. Rate Limit دیتابیس خاموش و شرط بکاپ/Decrypt/Restore پیش از هر Migration حفظ شد. ابزار یا میزبان جایگزین برای دورزدن محدودیت قبلی Preview/مرورگر استفاده نشد.
