# S2 — امنیت کد، حریم خصوصی خطا و ضداسپم

تاریخ: ۲۰۲۶-۱۰-۰۸. مبنا: `690c1859352e448c36e47555c1546711f11a3ec6`، بستهٔ S1. شاخه: `security/code-hardening-s2-20261008`؛ تحویل مستقل و پیش‌نویس، وابسته به S1.

این مرحله رفتار کد پیشنهادی را اصلاح می‌کند؛ محیط زنده، دیتابیس، Policy، Secret، دامنه و مقصد اطلاع‌رسانی تغییر نکرده‌اند. پالت، چیدمان، حرکت، عکس و محتوای واقعی تغییر نکردند. Package و Lockfile یکسان با S1 هستند.

## قرارداد ضداسپم و هزینهٔ در دسترس بودن

- Replay با شناسه و Fingerprint معتبر پیش از مصرف Turnstile بررسی می‌شود؛ این ترتیب و تعارض Idempotency حفظ شده‌اند. Replay معتبر به توکن مصرف‌شده وابسته نمی‌شود.
- برای درخواست **تازه**، نبود توکن/اختلال Siteverify دیگر مجوز پذیرش تأییدنشده نیست. Retry سرویس یک بار و با کلید ثابت انجام می‌شود؛ خطای `internal-error` هم قابل Retry است. کلید Secret نامعتبر به‌عنوان نقص تنظیمات بازمی‌گردد.
- کد عمومی موجود `BOT_VERIFICATION_INVALID` یا `TEMPORARILY_UNAVAILABLE` استفاده می‌شود؛ متن و دادهٔ داخلی به کاربر برنمی‌گردند. فرم موجود اطلاعات را برای تلاش دوباره نگه می‌دارد.
- Transport Client در نبود توکن همچنان می‌تواند تقاضای Replay را ارسال کند؛ مرجع اجازهٔ ثبت تازه Edge است. مسدودکردن Client به‌تنهایی دفاع امنیتی محسوب نمی‌شود.
- مسیر Protected قدیمی که فعلاً Route عمومی آن را صدا نمی‌زند نیز از پذیرش no-token/service-error به ذخیره‌سازی جلوگیری می‌کند؛ Verifier آن پاسخ را تا ۱۶KiB می‌خواند و Redirect را دنبال نمی‌کند.
- این سیاست هنگام اختلال واقعی ضداسپم ثبت تازه را موقتاً متوقف می‌کند. این Tradeoff آگاهانه است؛ پذیرش درخواست تأییدنشده وقتی محدودکنندهٔ دقیق DB خاموش است، انتخاب مناسبی برای انتشار عمومی نیست.
- Flood اضطراری همچنان ۳۰۰ تلاش در ۶۰ ثانیه برای IP معتبر Cloudflare است؛ محدودکنندهٔ دقیق و Transactional تلفن/IP نیست. درخواست‌های دیگر/GET تحت این Guard قرار نمی‌گیرند. Replay نیز ابتدا از Flood Worker عبور می‌کند.
- `rate_limit_policy.enabled` تغییر نکرده و تا E2E موفق Preview باید false بماند. Edge مستقر قبلی هنوز همین تغییر را ندارد؛ بستهٔ کد با اصلاح محیط زنده یکسان نیست.

## Header و محدودیت خواندن

Headerهای پایه: `Referrer-Policy: no-referrer`، `X-Content-Type-Options: nosniff`، `X-Frame-Options: DENY` و `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()`.

Nonce در سیاست عادی HTML حفظ می‌شود. CSP ثابتِ غیرNonce روی Asset گذاشته نشده؛ HSTS/includeSubDomains هم پیش از اثبات HTTPS و دامنهٔ واقعی فعال نشده‌اند. Headerهای `_headers` طبق مستندات Cloudflare به پاسخ Worker اعمال نمی‌شوند، بنابراین هر دو مسیر مستقل پوشش داده شدند. Preflight بلوک امنیت و دقیقاً قاعدهٔ کش `immutable` تولیدشدهٔ Nitro را بررسی می‌کند؛ هدر اضافی یا Override تأییدنشده باعث شکست آن می‌شود.

| پاسخ                            | سقف                                                           |
| ------------------------------- | ------------------------------------------------------------- |
| عکس اصلی خصوصی                  | ۲۰MiB، ضمن حفظ محدودیت ۴۰ مگاپیکسل و Decode قبلی              |
| هر پاسخ Data API ساخت           | ۴MiB؛ این سقف سیاست حفاظتی فعلی است، نه بیشینهٔ تجاری کاتالوگ |
| Siteverify در Edge و مسیر قدیمی | ۱۶KiB                                                         |
| بدنهٔ درخواست عمومی             | ۱۶KiB، قرارداد قبلی حفظ شده                                   |

Content-Length کوتاه یا غایب سقف مجموع Chunk را دور نمی‌زند. خطای Parser متن خصوصی منبع را چاپ نمی‌کند. کاتالوگ بزرگ در مرحلهٔ محتوایی باید صفحه‌بندی صریح و کنترل کامل‌بودن داشته باشد؛ سقف نباید به قطع پنهان محتوا یا حذف بی‌خبر محصول تبدیل شود.

## قرارداد لینک

- WhatsApp: همان دو میزبان `wa.me` و `api.whatsapp.com`، شمارهٔ بین‌المللی عددی و Query محدود؛ Credential/Port و پارامتر تکراری رد می‌شوند.
- Telegram: لینک HTTPS مستقیم به Username عمومی در `t.me` یا `telegram.me`؛ لینک دعوت/اشتراک/Redirect و Query پشتیبانی نمی‌شوند.
- Instagram: پروفایل عمومی در میزبان دقیق Instagram؛ مسیرهای اقدام یا Query پذیرفته نمی‌شوند.
- Website: HTTPS با Host غیرمحلی از نظر نحو، بدون Query/Fragment؛ مسیر زبان مثل `/en/` ممکن است. این کنترل مالکیت یا وجود DNS را اثبات نمی‌کند.
- Map: مسیر مکان/نقشه در میزبان‌های مشخص Google Maps، OpenStreetMap، Neshan و Balad؛ Redirect و URL تو در تو در Query پذیرفته نمی‌شوند. نقشه Embed یا SDK اضافه نشده است.

فرمت‌ها با Fixture مصنوعی آزموده شده‌اند؛ مالکیت حساب، نشانی واقعی و مقصد Redirect کوتاه‌شده باید پیش از انتشار با اطلاعات واقعی برند بررسی شوند. شمارهٔ تماس همچنان Constraint موجود DB را دارد؛ Canonical و Domain واقعی در مرحلهٔ پذیرش مقصد بررسی می‌شوند.

## اعتبارسنجی

- نصب جدا با Frozen Lockfile؛ Audit تازه `{}` و صفر Advisory شناخته‌شده.
- **۷۸۶ آزمون موفق، صفر شکست، ۶۸ فایل**؛ ۳۰ آزمون افزوده نسبت به S1. تست‌های قدیمی حذف، Skip یا ضعیف نشدند؛ انتظار Fail-open به انتظار صریح ۵۰۳ تغییر کرد.
- Lint: صفر Error و ۲۹ Warning قبلی؛ TypeScript، Edge check، Content check و Build موفق.
- Prepare/Verify Artifact و Wrangler strict dry-run با Metrics/Error Reports خاموش موفق؛ هیچ Upload یا Deploy اجرا نشده است. نتیجهٔ CI همان Head در PR/گزارش جامع ثبت می‌شود.
- آزمون واقعی تابع Edge با Env/Fetch تزریق‌شدهٔ آفلاین: نبود Proof، Host/Action غلط، پاسخ مثبت معتبر، ۴۰۰، اختلال مکرر، Retry/Idempotency، Secret نامعتبر، JSON/UTF-8/حجم نامعتبر؛ هیچ سرویس زنده فراخوانی نشد.
- Reader با مرز دقیق، UTF-8 چندبایتی میان Chunk، Content-Length کوتاه/بزرگ، Cancellation، Lock و خطای امن آزموده شد.
- Sink واقعی Console در Process جدا و دو Hook مرز خطا با دادهٔ خصوصی مصنوعی آزموده شدند؛ آرگومان خام/Context/Stack/Path عبور نکرد.
- CLI با دادهٔ آفلاین معتبر و لینک نامعتبر اجرا شد؛ مقدار حساس مصنوعی و کلید Fixture در خطا/Artifact نیستند.
- Guard بدنهٔ Streaming علاوه بر Bun، با تابع واقعی Bundleشده در **Node 24.19.0** آزموده شد: پاسخ ۴۲۲ به‌موقع و لغو Stream موفق.
- Headerها در Responseهای مصنوعی عادی/خطا/Redirect/بدون بدنه و خروجی واقعی Build بررسی شدند؛ این آزمون HTTP محیط مقصد یا مرورگر نیست.
- اسکن Source یک URL دارای Credential مصنوعی در تست رد لینک را گزارش کرد؛ مقدار آن Fixture آشکارا ساختگی است و برای اثبات رد Credential لازم است. تطبیق حذف/Ignore نشد؛ Secret واقعی در یافتهٔ بررسی‌شده نیست و خروجی عمومی صفر تطبیق داشت. اسکن الگو اثبات نبود تمام Secret/PII یا بررسی Log زیرساخت نیست.

## اثر بر حجم و مرز پذیرش

در همان وضعیت بدون محتوای واقعی، Graph کامل Static Import اولیه از **۴۴۶۷۹۹** به **۴۴۷۱۰۶** بایت خام و از **۱۳۷۹۴۴** به **۱۳۸۰۵۷** بایت gzip رسید: **۱۱۳ بایت افزایش gzip**. CSS همان ۲۶۲۷۶ بایت خام/۶۲۴۸ gzip و فونت‌ها همان ۱۳۰۹۷۲ بایت‌اند. کتابخانه یا وابستگی جدیدی اضافه نشده است. روش و اعداد در [JSON اندازه‌گیری](security-s2-bundle-summary-20261008.json) ثبت شده‌اند.

این اندازهٔ خروجی است؛ افت درصدی سرعت، LCP/INP/CLS یا سئو از آن محاسبه نمی‌شود. آمادگی محتوا هنوز ۲۳ Blocked و ۳ Deferred دارد. Browser، Turnstile واقعی، Screen Reader، HTTP واقعی و ثبت آزمایشی تا کد پیگیری باقی‌اند.

خلاصهٔ بدون Stack عمداً جزئیات Debug را کمتر می‌کند؛ Eventهای ثابت و لاگ ساختاری نتیجهٔ Edge حفظ شدند. Retention، دسترسی Log، خطای سرویس‌های بیرونی و تنظیمات خودکار ابزارهای مقصد در S3 باید بررسی شوند؛ این بسته ادعای Redaction همهٔ زیرساخت را ندارد.

گام بعد **S3** است: جداسازی Preview، وصلهٔ Postgres، بکاپ ماندگار و Restore فایل‌های اصلی، ACL آینده و تنظیمات محیط. تغییر زنده/Migration/انتشار فقط با Gate و مجوز مربوط انجام می‌شود.
